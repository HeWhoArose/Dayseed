## Deferred or unapproved scope

- **H5 XP/rank and social comparison:** not approved for v1; no acceptance case should block core release unless scope is explicitly changed.
- **Online accounts, Dayseed-managed cloud backup, cross-device sync, AI processing, ads/purchases/subscriptions:** excluded from initial v1 and gated separately.
- **Journal photos/audio/attachments and any unapproved search enhancement:** do not silently add; retain only expressly approved v1 scope.
- **Optional partial-progress tips:** exact cadence and copy remain open; decide to specify fully or defer them rather than ship unspecified notifications.

## Traceability gaps to close before the planning gate

2. Have the owner accept or explicitly defer the proposed quiet-hour/cap/collision/late-delivery and partial-tip defaults mapped in AC-011/AC-012; resolve or defer retrospective journal prompt eligibility/frequency.

## Status rules

- A policy appearing in this matrix means it is documented, not implemented.
- “Approved” refers to an owner-recorded policy decision; it does not establish runtime correctness.
- “Delegated default” means the default is proposed for planning and can be overridden by the owner before complete schema approval.
- No build, test, APK install, device validation, migration, or implementation audit is claimed by this matrix.
